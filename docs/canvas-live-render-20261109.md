# 画布恢复实时页面渲染（2026-11-09）

本轮根据“减少运动渲染机制”的反馈，移除自动位图快照及运动期间的显示替换，没有回退业务功能或直接恢复旧提交。

## 核对旧版

`2732e91` 已包含 HTML iframe、编辑和渐进水合，也有 ResizeObserver。旧版相机通过 Vue 的 computed 样式更新，平移和滚轮各用 rAF 合并。旧连线层为 60000×60000，不能为了单容器变换把它一并恢复。

本轮开始时的实现已经使用浅响应式相机、帧合并和 opacity 显隐。手势期间暂停水合调度，不是每个输入样本都会重算整页。因此，用户引用报告里的 display 切换、逐事件响应式更新并不完整对应当时的代码。“一个容器就是一个 GPU 图层”“固定快十倍”等结论没有测量支持。

## 当前实现

- 删除 `canvasSnapshot.ts` 及仅验证该模块的 11 项测试，不再安装捕获观察者、克隆生成页 DOM、序列化 SVG、解码和维护运动预览位图。
- 移除运动预览 canvas、线框占位和 `is-navigating`。移动时不切换 iframe 的透明度、可见性、阴影或标题毛玻璃。
- `PageCanvas.canvasNavigation` 仅负责 iframe 输入桥接，与页面渲染和截图无关。空格、中键、滚轮、快捷键及结束手势的处理保留。
- 绘制使用单一 rAF，移除 24ms 定时器竞争。输入样本顺序、缩放锚点、末帧同步刷新、聚焦取消旧任务和相机保存保留。
- 原型画板继续由同一相机容器移动。连线和操作胶囊保留独立的视口裁剪层，从同一个已绘制相机写入变换；没有恢复巨幅 SVG。
- 按需挂载和已编辑文档保留；元素历史快照、导出、安全策略、权限和后端均未更改。

## 验证

前端 187 项测试通过，TypeScript 检查和生产构建通过。原先 198 项中的 11 项属于已移除的运动位图模块。

浏览器使用真实工作台和项目 182 的页面副本，后续创建、锁定、保存均由测试夹具拦截到项目 900001 的内存数据，没有真实项目修改或 AI 调用。

- 72 个画板块、6 个已挂载原型 iframe 的同一场景中，运动预览由 4 张变为 0，备用占位由 6 个变为 0；手势期间所有 iframe 保持 opacity 1、visibility visible，手势前后文档身份相同。
- 生成页标题通过原生拖动由页面坐标 25/370.5 移到 61/385.5；属性修改文字后，切换设计／交互仍保留坐标、文字和同一元素／文档。
- 新建空白画板并插入标准按钮；画布平移／缩放后重新点选，修改文字和宽度 220px，原文档和组件节点保持，选框显示、鼠标事件恢复。
- 绘制 100×69px 矩形，撤销后消失，重做恢复；按钮的文字和宽度保留。

自动化窗口在不同轮次会再次最小化，rAF 采样存在约 1 秒的节流。已尝试恢复窗口并记录限制，未把这些样本当成可靠 FPS 或输入到显示的延迟对照，也未据此宣称完全恢复旧版手感。前后指标仍保存在任务工件中，供诊断使用。

完整刷新工作台即可加载新前端模块；已有 HTML 无需重新生成，后端无需重启。
