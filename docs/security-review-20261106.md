## 行为与边界

- 原型 HTML 中的自定义／生成 JavaScript 不作为受信代码执行。弹窗、跳转、开关、标签等由项目自带运行时提供；旧页面仅由自定义脚本实现的特殊效果需要迁移到该契约。
- 同源权限用于宿主编辑，因此 iframe sandbox 本身不是隔离任意 JavaScript 的边界；保护依赖净化、CSP 和项目受信运行时。不支持在此模式执行任意用户脚本。
- 图片二进制资源仍保持现有直链方式（包括 `/api/assets/**` 的图片、`/files/**` 和已有上传文件）；本次没有承诺素材文件已经私有化。若要求图片本身也只能由项目成员读取，需要另做受权图片交付或签名 URL。
- 项目内容允许免登录只读访问，这是用户确认的产品要求。成员信息、审计记录仍要求登录或管理员权限；保存、生成、删除等修改仍校验原有角色。本次没有新增“仅成员可读”或匿名分享令牌功能。
- 编辑会话锁仍是单后端实例内的锁。多实例部署需共享锁存储或数据库锁；本次没有宣称 compute 提供跨实例排他性。
- CSS、图片和节点标识保持可编辑；安全净化发生在文档装载和 HTML 导入时，不进入鼠标／滚轮高频路径。导出会移除临时策略和 nonce。
- 组件库缩略图也会净化保存的 HTML，额外移除全局样式表；缩略图容器不可聚焦交互，并隔离其布局和绘制，避免组件样式扩散到工作台。

## SVG 素材安全修复（2026-11-12）

- 确认存储型 XSS 风险：原上传接口只检查扩展名和大小，SVG 原样写入数据库与磁盘；素材响应未设置脚本限制。普通 `<img>` 使用 SVG 时通常不执行脚本，但直接打开同源 SVG、作为文档嵌入时不能依赖图片模式的限制。`/files/**` 还可访问历史磁盘副本。
- 上传前使用禁用 DTD、外部实体、外部 Schema 和 XInclude 的 XML 解析器，按静态 SVG 元素白名单校验。拒绝 script、事件属性、foreignObject、SMIL、外部 href、外部 CSS URL、CSS 导入和 XML 样式表指令；非法 XML 失败关闭。保留普通路径、文字、CSS、局部 use/渐变/蒙版/滤镜及嵌入式 PNG/JPEG/GIF/WebP。拒绝时不入库、不写磁盘，不通过正则删标签改变原图。
- 读取历史数据库和磁盘 SVG 时执行同样校验；安全拒绝不会被吞成数据库未命中并回退到另一份文件。历史文件不做破坏性迁移或删除。
- 为 `/api/assets/**` 与 `/files/**` 的响应统一添加 `Content-Security-Policy: sandbox; default-src 'none'; script-src 'none'; style-src 'unsafe-inline'; img-src data:; object-src 'none'; base-uri 'none'; form-action 'none'`，以及 nosniff、no-referrer、no-store。沙箱不授予 allow-scripts 或 allow-same-origin，覆盖直接打开旧文件、HEAD 及 Range 响应；不把这份资源策略施加到项目 HTML/API 或应用页面上。
- Nginx 的 `/api/` 和新增 `/files/` 代理使用 `^~` 前缀，防止 `.svg` / `.png` 等扩展名被前端静态资源正则规则抢先接管。Docker 部署需重新构建前端镜像以更新 Nginx 配置；本机 Vite 已代理这两个前缀。
- 正常图片继续公开展示，上传仍要求登录，匿名项目只读权限保留。SVG 仅支持上述静态素材能力；包含脚本、动画、外链或不支持 XML 扩展的文件需重新导出或转为 PNG。未审计或宣称历史上没有被利用，也未执行批量内容删除。

验证：46 项针对性回归通过，其中包括全部 67 个内置 SVG；完整默认后端回归 421 项中 397 项通过、24 项数据库/付费模型/视觉集成检查按原开关跳过，零失败。独立文件名的可执行后端 JAR 打包成功；按本机 Windows 路径与本地代理地址适配后的实际 Nginx 配置通过 `nginx -t`。隔离浏览器重放真实 MVC 响应：无保护的 SVG 对照文件执行 script/onload；两条受保护路径均未执行，并因独立源而无法读取 localStorage。普通 `<img>` 尺寸、渐变颜色和同源 Canvas 取像素正常。验证使用临时数据和 mock 数据库，没有写入真实素材或调用真实 AI。

## 会话缓存过期与容量修复（2026-11-12）

- 确认原 `sessionCache` 的 `ConcurrentHashMap` 无容量和主动过期维护：用户不退出、也不再使用过期凭证时，缓存会保留至进程重启。原有显式过期检查仍会拒绝过期 Token，不能据此认定凭证永久有效或已经发生 OOM。
- 引入 Spring Boot 管理版本的 Caffeine，将会话查询缓存声明为独立 Bean。默认最大容量为 10,000，可通过 `wireforge.auth.session-cache-max-size` / `WIREFORGE_SESSION_CACHE_MAX_SIZE` 调整；0 表示禁用缓存，负数启动失败。环境变量示例与 Docker Compose 已配套。
- 按会话数据库字段 `expiresAt` 的实际剩余时间设置到期；读取不续期，替换也不重置为新的七天。使用 Java 17 的系统调度器，在无请求时安排过期维护。物理回收按定时轮时间片执行，鉴权继续独立检查真实到期时间。
- 缓存淘汰不删除有效数据库会话；未命中时按 Token 原子加载数据库，同 Token 并发回源合并。未知 Token 不保留为缓存项。登录有效期维持七天，重启后仍可从数据库恢复登录。
- 退出先删除持久化凭证，再失效缓存，避免并发数据库回源使已退出的会话重新留在缓存。没有新增淘汰时删库的回调，也没有引入 Redis 或调整项目读写权限。

验证：新增 16 项回归，覆盖实际到期边界、读取与替换不续期、无请求时的后台清理、容量限制、无效日期、数据库回源、并发加载与退出竞争。43 项会话／权限相关检查通过；完整默认后端回归 437 项中 413 项通过、24 项数据库／付费模型／视觉集成检查按原开关跳过，零失败。使用可控时钟与调度器验证过期清理，没有等待七天或调用真实 AI。
