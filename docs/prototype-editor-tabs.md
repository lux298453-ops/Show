# Generated HTML editing and peer tabs

The existing generated HTML and saved interaction lines are used directly. No AI regeneration or database migration is needed for these frontend changes.

## Routing

`canvasRouting.ts` installs a capture listener before generated scripts. It resolves current saved relations by DOM UID, falling back to element ID, before a local `data-wf-tab` handler can consume the click. Updated relations are sent to this listener without reloading the iframe. User relations win over AI relations for the same UID. Ordinary unlinked local tabs retain their generated behavior.

## Preview

`previewTabs.ts` identifies peer tabs from DOM semantics, without relying on page names. `PreviewPageStack.vue` retains at most six attached page iframes and preloads at most four directly linked peer tabs. Existing nodes are not reordered when switching. Pure preview, the workbench simulator, and floating mobile preview share this component. Peer switches skip push animation and do not add back-history entries; ordinary page navigation keeps back history.

Pages are still separate HTML documents. Each page retains its original header and content styling; this change does not transplant one generated header into another page.

## Editing

Semantic cards, including button roots, support drilling into their text, image, and SVG children. A subsequent drag keeps the selected child. Generated elements can activate editing just like legacy components, subject to the existing read-only and interaction-mode guards.

The first manual geometry edit to a managed artwork image records its current fitted geometry and releases its generated `!important` constraints. Release covers both service-marked styles and unmarked generated styles, including legacy images already carrying `data-wf-layout-edited`. A separate `data-wf-artwork-layout` marker keeps release local to the edited image and lets snapshot restoration recover the original fitting rules. The marker and CSS exclusion are included in saved HTML. Image coordinates use the page coordinates shown by the inspector while CSS offsets remain relative to the original containing block.

In edit mode, managed artwork receives pointer events even when a decorative wrapper disables them. If a negative-z illustration is behind its own transparent section in the hit-test stack, selection resolves that section's actual image descendant. It never picks through unrelated foreground buttons, locked/hidden ancestors, or interactive preview. This recovery also applies to double-click image replacement. Preview retains the original pointer behavior and stacking order.

Layer dragging and bring-to-front/send-to-back share the same paint-order implementation. All prototype siblings participate, including inserted components with z-index 9999; editor controls are excluded by their injection markers/identities, rather than a numeric threshold. Ordering reads computed z-index (including generated stylesheets) and writes persistent inline priorities without moving DOM children, so Flex/Grid layout positions stay intact. Static children of ordinary containers receive relative positioning so their z-index takes effect; static Flex/Grid items retain their layout. Changes emit before/after history snapshots and are included in saved HTML.

Generated containers now publish nested text, image, button and container layers too; SVG paths stay atomic. Named containers and wrappers that create a stacking context are retained in the tree. Bring-to-front/send-to-back updates the selected element's wrapper branches inside its owning card, dialog, page or explicit component/group, so a nested image can actually rise above a title in that frame. Dragging descendants of different layout wrappers orders their branches at the common parent and explains when the containing branch moves. Explicit frame/group boundaries cannot be crossed this way; select the parent card/group to change its order. Nodes are never reparented.

Right-clicking a sidebar row resends its selected UIDs even when the sidebar already marks it selected, because reloading the iframe clears the canvas selection independently. Restack commands also carry explicit UIDs, so their target does not depend on a stale canvas selection.

Editors have a per-document lifecycle controller. Unloading synchronously disposes input/message listeners and selection controls after the pending save completes; reactivation cancels an older pending unload. Hydration checks for an active controller rather than trusting a leftover transform box or stylesheet. PageCanvas owns unloading when the LRU loadEditor prop changes, avoiding duplicate unload requests from its parent. Property edits can recover an inactive editor before sending their command.

Inspector X/Y values use page coordinates, matching the geometry commands. OffsetLeft/offsetTop are relative to a containing element and must not be used as page coordinates for generated nested text or artwork.
