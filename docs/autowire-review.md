# 智能连线审核与排除

保留画布原有的「AI 拓扑智能连线」入口。点击后先生成审核清单，确认后才保存关系。

## 使用流程

1. 点击智能连线。弹窗立即显示进度；有待保存编辑时先提交原型的待保存内容，保存完成后自动开始检查，无需再次点击。
2. 在左侧按来源页面选择关系，中间预览来源页面并定位触发控件，右侧预览目标页面。新增与修改统一放在「设置关系」；删除旧线、无法直接处理的冲突和不再推荐分别查看。规则明确的新增或补全可默认勾选；目标修改、页内动作转换、删除和 AI 建议需要主动选择。
3. 取消勾选只跳过本次。在「更多设置」的「后续推荐」中选择「以后不再推荐这条跳转」或「以后不再推荐此控件的关系」，保存后会记住选择，并清理对应的已有自动关系。默认「继续推荐」不代表本次一定创建，创建仍取决于勾选。
4. 在「不再推荐」中选择恢复，保存后下次打开智能连线会重新推荐。手动重新连接或撤销删除也会解除对应排除。
5. 选择或更换目标后，该条关系自动勾选。点击「应用已选（N）」即可：同一次请求内校验人工目标并保存所选关系，不需要「检查新目标」，也不会再次调用 AI。关系保存成功与原型预览更新分别反馈；预览失败可重试，不重复保存关系。

人工关系不会被智能连线覆盖。来源不明的旧关系列为「需要处理」。建议移除仅针对有明确自动来源的关系。
检查期间弹窗保持打开，避免继续编辑导致方案失效。保存失败或等待保存超时会显示具体原因；检查请求失败时错误留在弹窗中，可直接重试检查。重新检查不会再次保存未变化的原型，也不会自动重发应用请求。
已识别成组的导航使用专用规则，缺少业务标注也会进入导航预检。其他缺少依据的旧入口保留为「无法确定」，既有返回/关闭动作保留；不会仅因旧数据没有标注就建议批量删除。

## 导航补全

- 支持底部导航、带语义标记或明确文案的顶部和侧边导航。图标与文字按同一入口处理，导航几何区域不证明目标。
- 导航指纹包含版本、位置区域、排列方向及有序文案；同一项目内的同组导航才共享已确认目标，顺序不同的组不自动合并。
- 保留已有有效导航和人工关系。缺失目标优先使用同组已确认映射、唯一准确页面名；无法确定时使用局部导航截图或文字向 AI 请求建议，建议默认不勾选。
- 「全部 / 进行中 / 已完成」等内容筛选保持页内切换。已有 `tab_switch` 转为跨页导航需要审核；当前页自指不新增跨页线。
- 审核弹窗可筛选「仅看导航」。「跳转到」展示真实选中目标，选项值不再用空占位伪装已有目标；缺失目标明确显示「请选择页面」。选择后立即更新目标预览及完整关系句子，并可直接应用。
- 普通跳转或弹窗也支持人工选择目标：仅限有明确交互依据或单条已有自动跳转的实际控件。卡片、装饰、人工关系、来源不明与多条关系冲突继续受保护；无可选目标或需处理冲突时说明原因。预检仍不写入，未决建议初始不勾选；主动选择目标时自动勾选。
- 有可选目标的未决关系进入「设置关系」，有目标时可直接勾选，确认原建议目标无需重复选页。提交时同时携带所选关系与人工目标，服务端只校验并转换这些原条目，不扩展应用范围、不产生新 AI 建议；缺少目标或关系冲突时显示具体原因。
- 审核建议按来源页面分组，左侧选中条目只切换查看，勾选才决定应用。右侧展示「来源页面 → 触发控件 → 目标页面」及一行原关系。帮助、推荐依据、后续推荐设置与检查统计按需展开；页面筛选不会清空勾选，筛选外的已选项会在底部提示。
- 原有关系保存为检查时的快照，应用成功后的页面刷新不会改写对照内容。不再推荐针对原建议关系；设置排除时清除该条未保存的临时目标，保证显示内容与实际排除范围一致。
- 页面预览仅展示真实 HTML 或原设计稿，禁用脚本、表单和导航，不接入画布的编辑保存。来源控件优先精确匹配元素标识，回退可信坐标；无法定位时明确提示，不按相同文案猜测位置。普通单屏默认完整显示，可放大定位控件；长页面保持可读尺寸、独立滚动。目标为空时显示选择提示。
- 稳定项标识与决策指纹共同保存勾选、取消勾选及排除状态。目标、动作或依据改变后清空旧勾选；可选目标失效时丢弃旧目标选择。
- 折叠诊断展示已有关系、当前页导航、页内切换、排除与保护项。缺少完整元素分组时提示重新识别；不凭截图编造元素 ID 或点击区域。
- 同一入口多条关系或同组目标冲突，先在交互编辑中确认旧关系，再重新预检。排除记录优先于导航映射。
- 人工应用只处理勾选项，不能静默改写未勾选页面的已确认导航或共享映射。与既有目标冲突时整批拒绝，并明确已有来源页面与目标。普通人工目标同步持久化目标提示，避免旧提示在下次检查中否定刚确认的关系。
- 已审核的导航绑定优先挂在单个导航项包装层；无法找到可信包装层时，仅在演示模式启用透明热区。独立子按钮不被覆盖，不对图标和文字统一设置 `pointer-events: none`。
- App Map 使用相同分组与有效目标证据，缺少交互的图标不再直接判为当前页；不同指纹、冲突或同等规模的多套底栏不会合并。

## 关联依据与仲裁

- 优先补全已有交互中的明确目标引用，或读取绑定到实际元素的业务标注。
- 记录、规则、设置等明确导航入口采用准确页面名匹配；名称相似、商品名称、组件类型和位置接近不能单独证明跳转。
- 普通卡片和重复陈列卡片默认不连线。卡片内存在独立操作控件时由该控件承担交互；整卡仅在有整卡业务依据且没有独立子控件时参与推导。
- 图片、价格、装饰文字、分组成员不会各自生成跨页关系；本地状态动作保留。
- AI 仅评估有业务依据的未决关系，从服务端限定候选中选择目标并返回依据引用；目标越界或缺乏引用的结果不接受。
- 页面重新识别和交互提取的新自动结果同样经过卡片与排除校验。

## 服务端约束

| 接口 | 行为 |
| --- | --- |
| `POST /api/projects/{id}/autowire/preview` | 只读预检，不保存关系、不改 HTML；返回服务端方案标识，有效期 20 分钟 |
| `POST /api/projects/{id}/autowire/apply` | 提交方案标识、选择项 ID、可选人工目标、排除与恢复项、幂等键；定向校验目标与原关系，单事务应用，不调用 AI |
| `GET /api/projects/{id}/autowire/applications/{applicationId}` | 分别返回已保存数量及预览更新状态 |
| `POST /api/projects/{id}/autowire/applications/{applicationId}/retry-render` | 重试失败的预览更新 |

旧的 `autowire-ai`、`autowire-interactions` 手动接口也改为只读预检，避免旧调用绕过审核。后台分析的确定性补链使用相同规则，只应用明确的新增与补全，不自动移除。

方案保存在服务端内存，服务重启后需要重新预检；成功应用的幂等记录持久保存，同一请求重试返回原结果。页面、元素、关系或标注在审核期间发生变化，服务端返回 409 并拒绝所有变更。画布位置和标注框位置不影响方案有效性。

四张表由启动迁移创建：`interaction_exclusion`、`autowire_application`、`autowire_render_job`、`project_navigation_mapping`。导航映射只随已审核应用在同一事务保存；源关系失效或目标页删除后不用于补链。每次应用保存变更前关系、排除与导航映射快照。项目删除同时清理这些记录。

排除记录同时使用元素 ID 与页面内精确指纹。重新识别后仅在类型、文案、素材、取整几何位置一致且唯一时继承排除；变动或重复导致无法匹配时显示「元素已变化，待确认」，不会模糊绑定到其他商品。

关系事务提交后，持久任务构建一次 App Map，更新受影响页面的交互绑定；共享导航发生变化时补更新依赖该导航的页面。保留原有 HTML/CSS 布局，以比较并更新防止覆盖同时保存的内容。手动连线和删除也在提交后更新绑定；崩溃后待执行任务可恢复，失败任务等待重试。

旧 HTML 缺少元素标识时，只有精确文案、相近几何位置且唯一的 DOM 节点才可绑定；无法准确映射时前端提示检查对应元素。新模板包含 `data-wf-element-id`。此机制不会猜测修改不明确的节点。

## 验证

- 前端：`npm run build`（Vue 类型检查与生产构建）。
- 工作台浏览器回归：启动端口 5174 的前端后执行 `node tests/workbench-interaction-browser.mjs`，默认使用本机 Chrome，可通过 `NAV_TEST_BROWSER` 指定浏览器。接口全部模拟，不写入真实项目。覆盖 iframe 内空格与中键拖拽、连续拖拽、输入空格、失焦复位、绘制工具临时平移，以及单次点击等待保存、失败持续显示与重试。
- 勾选记忆：在前端目录执行 `node --test tests/autowireReviewState.test.ts`（Node 24）。
- 页面预览：执行 `node --test tests/autowire-preview.test.mjs` 和 `node tests/autowire-preview-browser.mjs`，覆盖精确控件定位、长页面滚动、设计稿回退、资源地址及只读隔离。
- 对照审核：前端启动于端口 5174 后执行 `node tests/autowire-compare-browser.mjs`，默认使用 Chrome。接口全部模拟；覆盖真实工作台弹窗、完整预览与放大、来源高亮、直接提交目标、幂等重试、暗色和窄屏，以及只重试预览更新而不重复保存关系。截图可由 `AUTOWIRE_SCREENSHOT` 指定路径。
- 后端：`mvn test`（默认不连接集成测试数据库）。
- 导航浏览器回归：先运行 `mvn test` 导出真实后端绑定夹具，再在前端启动 `npm run dev -- --host 127.0.0.1 --port 5174 --strictPort`，执行 `node tests/navigation-browser.mjs`。使用本机 Edge，可通过 `NAV_TEST_BROWSER` 指定 Chrome；API 与外部请求被阻断。覆盖真实 PageCanvas 的图标、文字、空白热区、独立按钮保护、编辑隔离、勾选与搜索记忆、人工目标直接应用、排除恢复和冲突保护。
- 本地 MySQL 集成验证：`mvn -Dwireforge.integration=true test`，使用 dev 配置和随机 HTTP 端口，创建带 `__autowire_test__` 前缀的独立临时项目并清理。
- 集成覆盖只读预检、原子拒绝过期方案、幂等提交、排除与恢复、画布删除与人工恢复、卡片误线处理、重新识别防复发，以及真实浏览器点击跳转与弹窗开关、后续更新保留原有弹窗绑定。

已有用户项目需要在审核弹窗选择应用才会清理历史误线；升级不会直接删除历史关系。
