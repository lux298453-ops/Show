# 内部设计稿转可交互线框原型工具——需求文档与开发计划

**版本**：v1.0
**日期**：2026-08-18
**作者**：产品与开发协作组
**状态**：评审稿

------

## 1. 项目概述

### 1.1 背景

在产品研发过程中，设计团队会输出大量 UI 设计稿图片（PNG/JPG）。产品、开发、测试及外部合作方需要快速理解设计意图、功能模块与交互流程。目前缺少统一的工具将这些静态图片转化为可交互的线框原型，并附上清晰的上下文说明，导致沟通成本高、对齐效率低。

### 1.2 目标

建设一个内部 Web 工具，支持上传设计稿图片，自动识别 UI 元素并生成可交互的线框原型，同时提供标注说明功能，帮助内部产品人员、外部合作方及普通用户直观理解产品功能和玩法。

### 1.3 范围

- **包含**：设计稿图片管理、AI 自动识别生成线框、交互配置（页面跳转、弹窗、下拉菜单、轮播、表单输入模拟、过渡动画）、标注说明、预览分享。
- **不包含**：用户权限体系、复杂协作功能（评论、版本回溯）、移动端适配、对外公开部署。

### 1.4 成功标准

- 从上传设计稿到生成可交互原型的时间不超过 5 分钟。
- 自动识别的元素准确率 ≥ 80%（允许人工微调）。
- 说明文字自动提取准确率 ≥ 90%。
- 内部用户满意度达到 4.2/5.0。

## 3. 竞品分析

### 3.1 Lovable

- **定位**：AI 全栈应用构建平台，通过自然语言或设计稿图片生成可运行的 Web 应用。
- **核心能力**：上传设计稿后，利用多模态大模型识别 UI 元素，映射到组件库，并推断交互逻辑，生成可编辑的 React 应用。
- **优势**：自动化程度高，输出真实代码，交互丰富。
- **劣势**：生成结果偏向高保真应用而非线框原型；需联网调用其服务，数据不私有；无法定制标注样式。
- **借鉴点**：多模态模型识别图片并映射组件；AI 推断交互；可视化编辑画布。

### 3.2 Uizard

- **定位**：AI 驱动的设计工具，将截图或手绘草图转换为可编辑的数字设计稿。
- **核心能力**：上传截图后自动识别 UI 元素，生成线框或高保真设计，支持配置跳转交互，可导出为 Figma 等格式。
- **优势**：专门针对 UI 截图识别，准确率较高；有原型交互功能。
- **劣势**：商业闭源，无法私有化部署；不支持自定义标注说明；交互配置需手动。
- **借鉴点**：元素识别算法、线框样式定义。

### 3.3 Visily

- **定位**：AI 设计工具，从截图或模板快速生成可编辑 UI。
- **核心能力**：上传截图，自动识别组件并生成设计稿，支持导出。
- **优势**：操作简单，组件识别能力强。
- **劣势**：不支持交互原型；不提供标注说明。
- **借鉴点**：截图到组件映射的预处理流程。

### 3.4 Anima

- **定位**：将设计源文件（Figma/Sketch/XD）转换为代码和原型。
- **核心能力**：从设计源文件提取图层和交互，生成 React/Vue 代码。
- **优势**：保留完整交互逻辑，生成代码可运行。
- **劣势**：依赖设计源文件而非图片；需要插件配合。
- **借鉴点**：交互模型的数据结构（页面、触发事件、动作）。

### 3.5 ComfyUI（画布交互参考）

- **定位**：节点式 AI 工作流工具，其前端画布支持拖拽节点、连线、参数配置。
- **优势**：画布交互优秀，支持复杂节点编辑。
- **借鉴点**：线框编辑器的交互设计（拖拽、缩放、连线、属性面板）。

## 4. 开源项目分析

### 4.1 screenshot-to-code（abi/screenshot-to-code）

- **简介**：使用 GPT-4 Vision 将截图转换为 HTML/Tailwind CSS 代码。
- **优势**：直接利用大模型生成前端代码，效果良好。
- **局限**：生成静态页面，无交互逻辑；输出代码而非结构化数据。
- **借鉴点**：提示词设计、图片预处理、模型调用方式。

### 4.2 tldraw

- **简介**：开源白板 SDK，提供画布、图形、文本、箭头等基础元素。
- **优势**：性能高、交互流畅、支持 Vue 和 React。
- **借鉴点**：作为线框编辑器的基础画布，处理元素拖拽、缩放、连线。

### 4.3 Vue Flow

- **简介**：Vue 3 的流程图/节点编辑器库。
- **优势**：原生 Vue 支持，适合构建交互连线（如页面跳转关系）。
- **借鉴点**：用于表示页面之间的跳转关系，以及元素与标注的连线。

### 4.4 Excalidraw

- **简介**：手绘风格白板工具，支持绘制线框、连线、文本标注。
- **优势**：轻量、易集成，标注功能完善。
- **借鉴点**：标注线的实现方式（黑色直线+文本框）。

### 4.5 Label Studio

- **简介**：开源数据标注工具，支持图像标注。
- **优势**：成熟的标注交互模式。
- **借鉴点**：元素标注的交互设计（框选、标签编辑）。

## 5. 功能需求

### 5.1 设计稿图片管理

- **上传**：支持拖拽或选择多个 PNG/JPG/WebP 图片文件，按项目分类存储。
- **目录扫描**：后端可配置扫描服务器指定目录（如 `/data/screens/`），自动同步图片文件。
- **预览**：图片列表缩略图展示，点击查看大图。
- **删除/替换**：支持删除或替换已上传图片。

### 5.2 AI 自动识别与生成

- **触发方式**：用户选择若干设计稿图片，点击“一键生成原型”。
- **识别内容**：
  - UI 元素类型（按钮、输入框、图片、文本、导航栏、卡片、列表等）
  - 元素位置、尺寸、样式（边框、填充色、圆角等）
  - 元素文本内容（通过 OCR 或模型直接提取）
  - 页面名称（根据图片文件名或模型推断）
- **交互推断**：模型基于常见设计模式自动推断交互：
  - 底部标签栏 → 点击切换页面
  - 卡片上的按钮 → 跳转到详情页
  - 带遮罩的层 → 点击打开弹窗
  - 图片轮播区域 → 自动播放轮播
  - 输入框 → 表单输入模拟
- **输出**：结构化 JSON 数据，符合预定义 Schema（见附录 A）。
- **手动修正**：识别结果可在编辑器中调整，包括元素属性、文本、交互配置。

### 5.3 线框编辑器

- **画布**：以设计稿图片为底图，上层渲染线框元素。
- **元素操作**：拖拽移动、缩放、对齐参考线、图层顺序调整。
- **样式**：支持修改线框元素样式（边框颜色、粗细、填充色、文本字体大小等）。
- **组件库**：提供线框组件（矩形、圆形、文本、按钮占位、输入框占位等），可手动添加。
- **撤销/重做**：支持操作历史。

### 5.4 交互配置

- **交互类型**：
  - 页面跳转：点击元素跳转到指定页面（页面下拉选择）
  - 打开弹窗：点击元素显示指定弹窗（弹窗内容为另一个页面或自定义元素）
  - 下拉菜单：点击展开下拉选项列表
  - 轮播：自动或手动切换图片/内容
  - 表单输入：输入框可输入文字，在预览中模拟
  - 过渡动画：页面切换或弹窗出现时可选淡入、滑动等动画
- **配置方式**：在属性面板中选择触发事件（点击、悬停）和动作，或使用连线模式连接页面。
- **预览测试**：编辑器内可快速预览当前交互效果。

### 5.5 标注与说明

- **标注元素**：支持在画布上放置标注点（小圆点），用黑色直线连接到文本框。
- **文本内容**：富文本，可编辑字体、颜色、大小，支持换行。
- **自动填充**：AI 识别时提取的元素文本自动填入对应标注框，允许修改。
- **说明面板**：页面右侧固定一个信息面板，汇总当前页面的所有标注文本，可折叠。

### 5.6 预览与分享

- **预览模式**：生成只读的交互原型，用户可点击元素触发配置的交互。
- **分享链接**：为项目生成一个只读访问链接，无需登录，可设置有效期（可选）。
- **嵌入支持**：提供 iframe 嵌入代码，方便在内部 Wiki 或官网页嵌入。

## 6. 非功能需求

- **性能**：识别单张设计稿图片时间 ≤ 30 秒；编辑器流畅度 60fps。
- **可靠性**：AI 识别失败时提示错误，保留原始图片不影响手动编辑。
- **易用性**：无需培训，产品经理可在 10 分钟内上手。
- **兼容性**：支持 Chrome、Edge 最新版本。
- **安全性**：内部使用，暂不考虑加密传输，但需防止外部未授权访问（部署在内网或加简单访问令牌）。
- **可维护性**：代码模块化，AI 模型可替换。

## 7. 技术方案

### 7.1 整体架构

text

```
前端 Vue 3 + TypeScript + Vite
  ├── 编辑器（Vue Flow 封装）
  ├── 预览器（自研交互模拟组件）
  └── 管理界面（项目、页面列表）

后端（暂定 Spring Boot 3，备选 Python FastAPI，详见《开源项目评估与架构方案》第五节）
  ├── REST API
  ├── 文件存储（本地磁盘或对象存储）
  ├── AI 模型调用（封装多模态 API）
  └── 数据持久化（MySQL，后续按需迁移 PostgreSQL）

AI 模型
  └── 中转站 ChatGPT API（OpenAI 兼容协议，支持 GPT-4o 等视觉模型）
```



### 7.2 前端选型

- **Vue 3 + Vite + TypeScript**：项目技术栈。
- **画布库**：Vue Flow（画布 + 页面跳转关系图双模式）。tldraw 生产环境收费，不采用（详见《开源项目评估与架构方案》1.3/六）。
- **状态管理**：Pinia。
- **UI 组件库**：Element Plus 或 Ant Design Vue。

### 7.3 后端选型

- **框架（暂定）**：Spring Boot 3.x（备选 Python FastAPI——复用 ScreenCoder Python 管线，理由见《开源项目评估与架构方案》第五节）。
- **数据库**：MySQL（MVP），后续按需迁移 PostgreSQL，存储项目、页面、元素、交互、标注等数据。
- **文件存储**：本地磁盘目录（如 `/data/screens/`），通过静态资源映射访问。
- **AI 集成**：调用中转站 ChatGPT API（OpenAI 兼容协议）。

### 7.4 AI 模型选型与提示词

- **模型**：统一使用中转站 ChatGPT API（OpenAI 兼容协议，支持 GPT-4o 等视觉模型；如成本或效果不达标，可切换国内低价模型）。
- **提示词策略**：
  1. 输入设计稿图片，要求模型输出严格符合 JSON Schema 的结构。
  2. 在提示词中明确元素类型列表、交互推断规则（如“底部有固定标签栏则推断为页面切换”）。
  3. 要求模型同时提取所有文本并填充到对应元素。
- **错误处理**：若模型返回格式非法，进行重试或降级为手动创建。

## 9. 开发计划

### 9.1 阶段划分

#### 阶段一：MVP（4 周）

**目标**：跑通核心流程——上传图片 → AI 识别 → 线框展示 → 手动编辑 → 预览。

- 后端项目搭建，数据库设计，文件上传接口。
- 集成一个多模态模型 API，实现图片识别并输出 JSON。
- 前端项目搭建，使用 Vue Flow 实现基本画布，加载识别结果。
- 元素拖拽、缩放、属性编辑（文本修改）。
- 简单的页面跳转交互模拟。
- 标注功能：手动添加标注点和文本框，支持连线。
- 基础预览模式。

**里程碑**：可演示内部 Demo。

#### 阶段二：功能增强（4 周）

**目标**：完善交互类型和用户体验。

- 实现弹窗、下拉菜单、轮播、表单输入模拟、过渡动画。
- 优化 AI 提示词，提高识别和交互推断准确率。
- 标注自动填充文本，说明面板侧边栏。
- 分享链接生成与只读访问。
- 编辑器撤销/重做、对齐辅助。

**里程碑**：内部试用，收集反馈。

#### 阶段三：优化与部署（2 周）

**目标**：稳定性和性能优化，准备上线。

- 识别结果缓存，批量处理。
- 错误处理与日志。
- 部署到内网服务器，配置静态资源。
- 编写使用文档，培训产品团队。

**里程碑**：正式投入使用。

### 9.2 总工期

预计 10 周完成 MVP 至正式版，可根据资源调整。

| 外部依赖不稳定        | API 调用失败             | 中   | 实现重试机制；失败后可切换备用模型                       |

## 附录 A：元素类型与交互动作定义

### 元素类型

- `button` 按钮
- `input` 输入框
- `image` 图片
- `text` 文本
- `container` 容器/卡片
- `navbar` 导航栏
- `list` 列表
- `icon` 图标
- `other` 其他

### 交互动作

- `navigate` 页面跳转
- `modal` 打开弹窗
- `dropdown` 下拉菜单
- `carousel` 轮播切换
- `input_focus` 输入框聚焦模拟
- `animation` 过渡动画（淡入、滑动、缩放）
