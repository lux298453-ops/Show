### 1.3 关键发现

2. **ComfyUI 的画布用的是 LiteGraph.js**（Canvas 2D 渲染的节点图编辑器），但文档薄弱、API 老旧，且 ComfyUI 整体是 GPL-3.0 许可证（传染性），直接复用代码会污染闭源项目。

3. **Vue Flow 是 Vue 3 项目做 ComfyUI 风格画布的唯一成熟选择**——MIT 许可证，原生 Vue 3 Composition API，内置缩放/平移/拖拽/连线/Minimap，n8n 和 Kestra 都用它构建节点编排界面。

4. **Excalidraw 是标注导引线的最佳选择**——130k star、MIT、可嵌入，但它是 React 生态，在 Vue 项目中需走 iframe embed 方案。

5. **ScreenCoder 的关键缺口**：输出是高保真 HTML，不是结构化 JSON；没有交互推断；没有线框化（低保真）转换；没有画布/编辑器 UI；没有预览/分享。这些是新建系统需要补齐的。

### 1.4 对标产品调研借鉴点（2026-08-19 补充）

调研 Visily / Balsamiq AI / Uizard / Figma Make / UX Pilot / Manus / Axure / ProtoPie / Penpot / draw-a-ui / wiremd / ProtoScan / Wireflow 等工具后的结论：

| 借鉴点 | 来源 | 落地方案 |
|---|---|---|
| 弹窗 = 普通页面 + overlay 标记，带 9 种定位 + click-outside 关闭 + 背景遮罩 | Penpot overlay 机制（`interactions.cljc`） | 弹窗复用 page 表 + overlay 标记；定位预设 center/top-left/manual 等；`close-click-outside`、`background-overlay` 参数，`target_element_id` 依赖去掉 |
| 交互 = 触发事件 × 动作类型组合 + 动画子模型 | Penpot `schema:interaction`（event-types / action-types / animation） | 交互 JSON 对齐 Penpot：event（click/mouse-over/after-delay）× action（navigate/open-overlay/close-overlay/open-url）；动画 dissolve/slide/push × duration/easing/direction，并做「action 与动画」合法性校验（如 push 不允许用于 overlay） |
| flow 一级概念：命名用户流 + 起始帧 | Penpot `schema:flow`（types/page.cljc） | 页面增加 `flows`（id/name/starting-frame），预览器顶部 flow 下拉切换（替代纯"跳转关系图"视图） |
| 文件数据整包 JSON + change 日志实现撤销/重做 | Penpot `undo_stack.cljc` / `changes.cljc` | 页面/元素/交互不拆细表，单 JSON 字段整体存储，编辑走 change 追加，撤销/重做基于 change 回放 |
| 转换层混合方案：几何走 bbox，分类走 VLM 直出 JSON | draw-a-ui / wiremd | `html_to_json.py` 降级为备选方案，避免解析 Tailwind 嵌套 div 的脆弱性 |
| 原型自检：死链接/孤立页面/未配置交互元素 | ProtoScan | 新增自检功能（阶段二实现），需求评审场景价值高 |
| 画布双视图：编辑器 + 站点地图 | Wireflow | Vue Flow 复用：画布模式 + 页面跳转关系图模式 |
| 标注/说明系统 = 差异化护城河 | Visily/Uizard/Balsamiq 均不支持 | 强化 AI 自动填充标注，作为核心卖点 |
| 导出可运行 HTML（P2） | 源流 / Open CoDesign | 复用 ScreenCoder 已有 `layout.html`，低成本扩展 |

**明确不采纳**：
- Axure 条件/变量/动态面板——交互深度够用即可，MVP 不做
- Quant-UX 可用性测试闭环（会话录制/热力图）——P2 后视需求再定
- Figma 文件解析方向（FigmaToCode/Grida）——输入仅为图片，路线不符

## 二、系统架构设计

### 2.1 技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Vue 3 + TypeScript + Vite | 需求文档指定 |
| 画布库 | **Vue Flow** (MIT) | Vue 3 原生，ComfyUI 风格拖拽/缩放/连线 |
| UI 组件库 | Element Plus | 需求文档指定 |
| 状态管理 | Pinia | Vue 3 标配 |
| 后端框架 | Spring Boot（暂定） | 待评审；FastAPI 论证见第五节 |
| 数据库 | MySQL (MVP) → PostgreSQL (生产) | 用户指定；先 MySQL，按需再迁移 |
| 文件存储 | 本地磁盘 | 内部使用，简单可靠 |
| AI 模型 | 中转站 ChatGPT API | OpenAI 兼容协议；ScreenCoder `utils.py` 配 base_url 指向中转站即可 |
| 标注导引线 | Excalidraw iframe embed (可选) | 或自研 SVG 连线 |

### 2.2 五层架构

```
输入层 → 分析层 → 转换层 → 画布层 → 预览层
```

#### 第一层：输入层
- **目录扫描**：后端 watchdog 监听指定目录（如 `/data/screens/`），自动同步新增设计稿
- **手动上传**：前端拖拽上传 PNG/JPG/WebP
- 按项目分类存储，生成缩略图列表

#### 第二层：分析层（ScreenCoder 管线，已有）
直接复用 ScreenCoder 的完整流程：
1. `block_parsor.py` — VLM 检测布局区域（header/sidebar/navigation/main content）
2. `html_generator.py` — 分区域用 VLM 生成 Tailwind CSS HTML 代码
3. `image_box_detection.py` — Playwright 渲染 HTML，提取灰色占位符 bbox
4. `UIED/run_single.py` — UIED 引擎检测原始截图中的 UI 组件
5. `mapping.py` — CIoU 对齐占位符与 UIED 元素
6. `image_replacer.py` — 用裁剪图片替换占位符

**输出**：`bboxes.json`（布局区域）、`layout.html`（完整 HTML）、`mapping.json`（元素映射）、`cropped_images/`（裁剪图片）

#### 第三层：转换层
这是连接 ScreenCoder 和前端画布的**核心桥梁**：

1. **HTML → 结构化 JSON**：用 BeautifulSoup 解析 ScreenCoder 生成的 HTML，提取每个元素的类型、位置、尺寸、文本内容、样式，转换为需求文档中定义的 JSON Schema 格式

2. **交互推断**：用 VLM 分析原始设计稿 + 已识别的元素列表，推断交互逻辑：
   - 底部标签栏 → 页面切换
   - 卡片按钮 → 跳转详情页
   - 遮罩层 → 弹窗
   - 轮播区域 → 自动播放
   - 输入框 → 表单输入模拟

3. **线框化**：将高保真 HTML 元素转换为低保真线框样式：
   - 图片 → 灰色矩形 + 对角线
   - 文本 → 占位横线或保留文本
   - 按钮 → 矩形边框 + 文字
   - 输入框 → 矩形 + 下划线

#### 第四层：画布层（Vue 3 + Vue Flow）
- **无限画布**：Vue Flow 提供拖拽/缩放/平移，完全 ComfyUI 风格
- **底图渲染**：设计稿图片作为画布背景层
- **线框节点**：每个 JSON 元素渲染为 Vue Flow 自定义节点（即 Vue 组件）
- **属性面板**：右侧面板编辑选中元素的类型/文本/样式/交互
- **交互连线**：用 Vue Flow 的 edge 系统表示页面跳转关系
- **标注系统**：SVG 导引线 + 文本框，AI 自动填充

#### 第五层：预览与分享
- **预览模式**：只读交互原型，点击元素触发配置的交互
- **分享链接**：生成带 token 的只读 URL
- **iframe 嵌入**：提供嵌入代码

这是整个系统的数据契约，ScreenCoder 输出 → 转换层产出 → 画布层消费 → 预览层执行：

## 三、实施路径

### 阶段一：后端管线整合（2 周）

**目标**：将 ScreenCoder 的 CLI 脚本封装为 FastAPI 服务，新增 JSON 转换层

1. 搭建 FastAPI 项目结构，将 ScreenCoder 的 Python 模块作为子模块引入
2. 封装 `main.py` 的流程为异步 API：
   - `POST /api/scan` — 扫描目录，返回新增图片列表
   - `POST /api/analyze` — 对指定图片执行 ScreenCoder 管线
   - `GET /api/results/{task_id}` — 获取分析结果
3. **新增 `html_to_json.py`**：用 BeautifulSoup 解析 HTML，提取元素树 → JSON Schema
4. **新增 `interaction_infer.py`**：VLM 提示词推断交互逻辑
5. **新增 `wireframe_style.py`**：高保真 → 低保真线框样式转换
6. MySQL 数据库，建表（project / page / element / interaction / annotation）
7. watchdog 目录监听

### 阶段二：前端画布 MVP（3 周）

**目标**：Vue Flow 画布 + JSON 渲染 + 基础编辑

1. Vue 3 + Vite 项目搭建，Vue Flow + Element Plus + Pinia
2. 项目管理界面（列表/创建/上传）
3. Vue Flow 画布：
   - 设计稿图片作为背景层
   - 自定义线框节点组件（button/input/image/text/container/navbar）
   - 节点拖拽/缩放/对齐
4. 属性面板：元素类型/文本/样式编辑
5. 标注系统：SVG 导引线 + 文本框
6. 加载后端 JSON → 渲染画布
7. 原型自检：死链接 / 孤立页面 / 未配置交互元素检测（参考 ProtoScan）

### 阶段三：交互与预览（3 周）

**目标**：完整的交互配置和预览能力

1. 交互配置：页面跳转/弹窗/下拉/轮播/表单/动画
2. Vue Flow edge 连线表示页面跳转
3. 预览模式：只读交互原型播放器
4. 分享链接生成
5. iframe 嵌入代码
6. 撤销/重做
7. 导出可运行 HTML（复用 ScreenCoder 的 `layout.html`，P2）

### 阶段四：优化与部署（2 周）

1. AI 识别准确率优化（提示词调优）
2. 批量处理 + 结果缓存
3. 错误处理与日志
4. Docker 部署
5. 使用文档

**总工期**：约 10 周（与需求文档一致）

## 五、为什么不用 Spring Boot

**当前状态：选型暂定**（2.1 技术栈表暂记 Spring Boot）。本节保留 FastAPI 论证供评审时决策：
需求文档原定后端为 Spring Boot 3，但若复用 ScreenCoder Python 管线，建议改为 **Python FastAPI**：

1. **ScreenCoder 是纯 Python** — 用 Java 需要重写全部 VLM 调用、UIED 集成、图像处理逻辑，工作量巨大且容易出错
2. **FastAPI 性能足够** — 基于 uvicorn + async，单机并发不输 Spring Boot
3. **AI 生态 Python 优先** — OpenAI SDK、DashScope SDK、Google GenAI SDK 都是 Python 原生
4. **前端不受影响** — Vue 3 + TypeScript 前端通过 REST API 调用后端，与后端语言无关
5. **类型安全** — FastAPI + Pydantic 提供与 TypeScript 对等的类型检查

## 六、ComfyUI 画布复刻方案

### 6.1 为什么不直接用 LiteGraph.js

- ComfyUI 使用 Comfy-Org/litegraph.js（LiteGraph 的 fork），但文档薄弱、API 风格老旧
- ComfyUI 整体 GPL-3.0，直接复用代码有传染性风险
- LiteGraph 是 Canvas 2D 渲染，Vue Flow 是 DOM/SVG 渲染，后者更容易自定义节点样式

### 6.2 Vue Flow 复刻 ComfyUI 交互

| ComfyUI 交互 | Vue Flow 实现 |
|---|---|
| 无限画布拖拽平移 | Vue Flow 内置 `panOnDrag` / `zoomOnScroll` |
| 节点拖拽 | 内置 `nodeDraggable` |
| 节点连线 | 内置 edge 系统，`connectionMode` |
| 缩略图 | `MiniMap` 附加组件 |
| 控制按钮 | `Controls` 附加组件 |
| 网格背景 | `Background` 附加组件 |
| 右键菜单 | 自定义 context menu |
| 属性面板 | 侧边 Vue 组件 |
| 节点折叠 | 自定义节点内部状态 |

### 6.3 线框节点设计

每个 UI 元素类型对应一个 Vue Flow 自定义节点：

```
button  → <WireframeButton>  矩形边框 + 文字
input   → <WireframeInput>   矩形 + 下划线 + 占位符
image   → <WireframeImage>   灰色矩形 + 对角线
text    → <WireframeText>    横线或文本
container → <WireframeCard>  圆角矩形
navbar  → <WireframeNavbar>  横向条带 + tab 标记
```

## 七、总结

**最优组合路径**：

```
ScreenCoder (截图→HTML管线，项目内已有)
    + 新增转换层 (HTML→JSON→线框化→交互推断)
    + Vue Flow (ComfyUI风格画布，MIT，Vue 3原生)
    + 后端服务（暂定：Spring Boot / FastAPI 评审后定，FastAPI 论证见第五节）
    = 完整的"设计稿→可交互线框原型"系统
```

**不需要引入的外部项目**：
- Penpot — Clojure 抽取不可行
- mydraft — 非 SDK，fork 成本高
- Wire-DSL — 11 star 停滞
- ComfyUI 代码 — GPL 传染性
- tldraw — 生产环境收费

**值得借鉴思路的**：
- draw-a-ui — 极简截图→代码管线
- wiremd — Markdown→线框→JSON AST
- screenshot-to-code — WebSocket 流式输出
- ComfyUI — 画布交互设计参考（不抄码）
