# WireForge 功能介绍文档

> **文档版本**：v1.0
> **最后更新**：2026-09-15
> **适用对象**：产品经理、设计师、交互设计师、评审人员、新加入的开发同学

---

## 一、一句话说明：这是什么

**WireForge 是一个"把 UI 设计稿变成可点击原型"的工具。**

你把做好的设计稿图片（PNG/JPG）丢进一个文件夹，它自动帮你做完三件事：

1. **看懂**：用 AI 逐页识别设计稿上有什么——按钮、标题、卡片、开关、底部导航……都在哪个位置、写的什么字、点了应该跳去哪；
2. **还原**：把识别结果渲染成一份**浏览器里能真正打开、能点击跳转**的高保真 HTML 页面，而不是一张死图；
3. **讲清楚**：为每个元素配一条中文业务说明，评审时能一眼看懂"这块是干嘛的"。

### 它解决的核心痛点

| 没有它 | 有了它 |
| :--- | :--- |
| 评审时对着设计稿图片口头讲流程，听的人跟不上 | 直接点着原型走一遍：点"抽奖"真的会弹出中奖结果 |
| 设计稿是静态的，看不出页面之间怎么串 | 跳转关系被自动识别并连线，一键验证有没有断链 |
| 讲清一屏的功能要写很长的文字说明 | 每个组件旁边挂着说明卡片，点一下手机里就高亮对应位置 |
| 一套设计稿要手工做成可点击 Demo，成本很高 | 导入 → 点一次"AI 生成原型" → 得到全项目可交互原型 |

### 它的定位边界（很重要）

它**不是**用来做像素级视觉还原、也不是直接产出可上线代码的工具。它的目标是把"设计意图"变成"可演练、可评审的东西"。所以：

- 颜色是**从原图采样**出来的真实色值，不是 AI 猜的，但排版是"按坐标直出"，不追求 100% 还原设计师的作品；
- 它**不能**替代设计师交付；它是给产品、开发、测试"提前看到完整交互"用的。

## 二、谁在什么场景下用它

| 角色 | 典型用法 |
| :--- | :--- |
| **产品经理 / 交互设计师** | 把设计稿变成可点击原型，做需求评审；给每个控件写业务说明，让开发看懂玩法 |
| **设计评审人员** | 在原型画布上逐屏看，标注哪里有问题；对比"设计稿原图"和"生成的原型" |
| **开发同学** | 提前知道每个按钮跳到哪、哪个是弹窗不是新页面，减少沟通成本 |
| **测试同学** | 用内置的自动化验证拿到"哪些跳转点不动"的失败清单，当回归用例 |

## 三、整体工作流程

从"一堆设计稿图片"到"可点击原型"，一共六个阶段。**前三个阶段与 AI 有关，后三个阶段完全由确定性算法完成、不消耗任何 AI 调用**——这是这个工具最核心的设计取舍，也是它能做到"稳定可复现"的关键。

### 第 1 阶段：导入（人做）

把设计稿图片按页面顺序丢进 `designs` 目录（可建子文件夹分组，如 `装扮修改/装扮首页.png`）。
然后在项目详情页点一次「**扫描设计稿**」，工具就会把每张图登记成一个"页面画框"。

> 为什么要分文件夹？因为有子目录时，页面名会自动带上分组前缀（`装扮修改/装扮首页`），后续找页面更方便。

### 第 2 阶段：AI 看懂设计稿（AI 做，最耗时、最花钱）

点一次「**AI 生成原型**」。这一步视觉大模型会逐张"看图"，输出一份结构化清单：

- 页面上有 **N 个元素**，每个元素的类型（按钮/文本/图标/开关…）、位置、大小；
- 每个元素上**真实写的什么字**（设计稿上没有文字的元素，AI **不允许**编造文字）；
- 每个元素**点了会发生什么**（跳转到哪一页 / 打开哪个弹窗 / 返回 / 切换选项卡）；
- 每个元素**一句话中文功能说明**（给评审看）。

**关键设计**：AI 只负责"看清楚并说清楚"，**不负责画画**。它不能决定颜色、不能决定排版——这些交给下一阶段。

### 第 3 阶段：交叉补全与对齐（大量确定性算法，无需 AI）

这是整个工具最"重"也最容易被低估的部分。AI 认得再好，不同页面之间也一定会有不统一的地方（同一个底栏在不同页里位置差了 3 像素、同一个按钮在两页里连到了不同目标）。所以识别完成后会自动跑一串**纠错与对齐**：

1. **补链**：AI 说"点了跳到《背包页》"，但《背包页》这个名字是分析完之后才确定的——这时按名称快照把目标 ID 补上去；
2. **变体对齐**：同一场景的不同状态页（如《个性装扮预览页》《形象待机页》《动效页》）的顶部导航、返回键、立绘框、底部托盘，会被强制吸附到完全相同的坐标，这样切换时不会跳动；
3. **交互自动布线**：见后文"功能四"，自动补齐返回键、底部 Tab、功能入口、弹窗唤起等跳转关系；
4. **App Map 共享底栏**：见后文"功能三"，所有页面共用同一条底部导航栏；
5. **全量重渲染**：用最终数据把所有页面重新生成一遍 HTML。

### 第 4 阶段：确定性渲染（零 AI）

把每个元素按**它自己的坐标**画到 375×812 的画布上，颜色从设计稿原图**逐像素采样**得到。
因为不经过模型，所以：**同一份数据渲染一万次结果完全一样**，也不会突然冒出奇怪的颜色和字体。

### 第 5 阶段：人工微调与标注（人做）

在原型画布上：拖页面区块、编辑业务说明、拖动排序、直接改页面上的文字/字号/位置。
所有修改自动保存。

### 第 6 阶段：预览与验证

点「**预览原型**」进入手机壳模拟器，像玩 App 一样点着走。也可以随时跑一次「**交互验证**」，让无头浏览器把所有可点元素真实点一遍，列出点不动的清单。

## 四、功能详解

> 下面每个功能都按同一个结构讲：**它是什么 → 什么时候用 → 你会看到什么 → 背后发生了什么**。

---

### 功能一：项目库（首页）

**它是什么**：所有原型项目的入口，相当于"文件夹列表"。

**什么时候用**：每次打开工具的第一站。

**你会看到什么**：

- 每个项目一张卡片：项目名、描述、创建日期、"N 个画框"、"N 已就绪"；
- 顶部有一个**搜索框**（按项目名和描述模糊匹配）；
- 右上角两个视图切换按钮：**网格视图**（卡片）和 **列表视图**（表格）；
- 点「**新建项目**」弹出表单，填项目名（如"电商大促移动端原型"，占位文案就是这个）和项目描述，点「立即创建」；
- 卡片右下角「**进入工作区 ›**」进项目；鼠标悬停卡片右上角出现删除按钮。
- 删除会弹二次确认："确定删除项目「xxx」吗？其下所有页面、元素、标注将一并删除，且不可恢复。"

**背后发生了什么**：

- 项目详情里的画框数是**异步并发拉取**的，所以列表先出来，数字后面再补上（你会看到"读取中…"）；
- 删除是**级联清理**的，会按"交互 → 标注 → 元素 → 页面 → 项目"的顺序删干净，不会留下垃圾数据。

---

### 功能二：项目详情页（设计稿管理）

**它是什么**：一个项目内部的管理台——负责"把设计稿导进来"和"让 AI 处理"。

**什么时候用**：刚拿到一批新设计稿时；或者设计稿有更新时。

**你会看到什么**：

- 顶部三个按钮：
  - 「**扫描设计稿**」——去目录里找新增的图片并登记为画框（图标会转圈，文案变成"扫描中..."）；
  - 「**AI 生成原型**」——对还没处理过的页面执行 AI 识别（文案变成"AI 解析中..."）；
  - 「**进入原型画布**」——去主工作区（没有画框时是灰的）；
- 中间可以看到**设计稿路径**（一个可点击的代码风格小方块），**点一下就复制到剪贴板**，方便你粘到文件管理器里直接放图；
- 每个画框卡片有缩略图和状态角标：「**已识别**」（绿色）/「**待分析**」（琥珀色）；
- 顶部有**状态筛选**：「全部 (N)」「已识别 (N)」「待分析 (N)」；
- 也有搜索框，可以按画框名筛。

**背后发生了什么**：

- 「扫描设计稿」是**幂等**的：同一张图不会被重复登记。它最多递归 3 层子目录，并且会**跳过任何叫 `assets` 的目录**（那个目录用来放素材，不是设计稿）；
- 「AI 生成原型」**只处理待分析的页面**。已经识别过的不会重跑——这是为了省钱。如果全部都已识别，它会提示你"所有页面都已有线稿，无需生成"；
- 同一个项目**不允许同时跑两个分析任务**，重复点会提示"该项目正在分析中，请等待当前分析完成"。

---

### 功能三：AI 认识设计稿（元素识别）

**它是什么**：把一张设计稿图片翻译成一份"元素清单"。

**什么时候用**：新导入设计稿后必做。

**它认得什么**：

AI 只能输出下面这 22 种类型之一，不能自由发挥（这样渲染器才画得出来）：

> 按钮、输入框、搜索框、文本、图片/立绘、图标、头像、容器/卡片、列表、顶部导航栏、页内选项卡、勾选框、单选框、开关、滑杆、进度条/血条、星级评分、徽标/角标、分隔线、背景图、特效/光晕、其他

**它被严格约束的几条规则**（这些规则的存在都是为了"别乱来"）：

| 规则 | 为什么要这样 |
| :--- | :--- |
| 文案必须**照抄**设计稿上的真实文字；设计稿上没有文字的元素，文案一律留空 | 防止 AI 自己编一个"结果展示槽""奖品展示区"写进画面，视觉上很干扰 |
| 图标类元素的文字写它的**含义**（如"返回""关闭""铃铛通知"），但引擎**不会把它画出来** | 图标已经画了，再叠一行字就是重影 |
| 位置必须是 `[x, y, 宽, 高]`，**不是右下角坐标** | 这是最高频的错误，提示词里专门用加粗例子讲了一遍 |
| 卡片/容器只写功能类别（"卡片""弹窗"），标题文案交给内部子元素 | 防止容器和子元素写同一句文案、两层重影 |
| 被遮挡了半截的角色立绘，也要整体框住完整空间 | 否则画面会缺一块 |
| 按钮上带的文字（如"x1兑换"）整体算按钮，不拆成"x1"+"兑换"两个元素 | 防止按钮上叠出多层碎片 |
| 半透明遮罩层只识别**前景弹窗**，不识别遮罩下透出的底层界面 | 否则会重复识别两次同一个界面 |
| 只有**视觉上真有底色或边框**的区域才算容器 | 防止平铺的几个卡片外面生出一个看不见的多余大框 |

**AI 还会顺手做两件事**：

- 给每个元素写**一句话中文功能说明**（这就是后面标注卡片的正文）；
- 给每个元素标**点了会怎样**：跳转 / 打开弹窗 / 返回 / 切换选项卡，四选一。

**关于"重新识别"**：

- 单个页面可以「**AI 重新识别**」（约 10–20 秒/页）；
- 也有全项目「**重新识别全部**」；
- ⚠️ 重新识别会**清空该页旧数据**再重建，是消耗 AI 额度最重的操作。

---

### 功能四：确定性渲染引擎（为什么它看起来"干净"）

**它是什么**：把元素清单"照坐标画出来"的渲染器。**全程不调用 AI。**

**为什么要有它**：早期版本是让 AI 直接"画 HTML"，结果每次生成都不一样，颜色乱、排版飘、要反复重试。后来改成"AI 只提取语义 + 引擎负责画"，问题一次性消失了。

**它怎么画**：

| 层 | 来源 | 效果 |
| :--- | :--- | :--- |
| **颜色层** | 从设计稿原图**逐像素采样**每个元素区域，得到真实的填充色和文字色 | 颜色一定是设计稿的色，不会突然变紫 |
| **结构层** | 图标 → 小方框；图片 → 采样色低饱和色块；文字 → 真实文本 + 字号自适应 | 输出稳定，不会乱 |

**它的几个自愈机制**（都是为了防止"看起来坏了"）：

- **防裂图**：如果 AI 引用了一个不存在的素材（比如编造了 `/api/assets/u-xxx`），渲染前会校验素材 ID 是否真实存在，不存在的 `<img>` 直接移除，而不是给你一个裂图；
- **防横向溢出**：注入一段保护样式，保证按钮文字不折行、图标不撑破容器；
- **高度自动回收**：如果实测渲染高度超出设计稿画布高 8% 以上，会自动等比缩回，不会出现"页面下半截是空白"；
- **防重复渲染**：容器内已有子元素时，抑制容器自身的占位行；导航栏里已有图标时，隐藏重复的子元素；文案完全相同且位置重叠超过 50% 的文本，只保留面积大的那个。

---

### 功能五：页面命名（为什么页面名总是对的）

**它是什么**：给每个画框取一个**确定性的、稳定的**名字。

**为什么重要**：所有跳转连线都是**按页面名**连的。如果 AI 每次分析给同一页取不同的名字（今天叫"首页"，明天叫"宠物家园首页"），那所有指向它的连线就全断了。

**命名顺序**（越靠前越优先）：

1. 文件名里有业务语义的（如 `壁纸设置@3x.png`、`宝箱弹窗@3x.png`）→ 清洗掉 `@3x`、扩展名等切图杂质后**直接采用**；
2. 文件名是纯数字或无意义导出名（`image.png`、`未命名.png`、`截图.png`）→ 改用图内 OCR 文字的强特征指纹命名；
3. 画板克隆衍生文件（如 `背包@3x-2`）→ 结合图内增量特征（出现"购买确认"）识别为子状态弹窗；
4. 以上都没有 → 才用 AI 建议的名字兜底。

**一句话**：**页面名 100% 由规则决定，不由 AI 掷骰子。**

---

### 功能六：App Map —— 全局共享底栏

**它是什么**：让所有页面的底部导航栏长得**一模一样**。

**为什么需要**：设计稿是逐页画的，每页的底栏位置、图标大小、文案都可能差几个像素。如果就那样渲染，用户点 Tab 切页时底栏会"跳一下"，很廉价。

**它怎么做到的**（纯投票算法，没有 AI 参与）：

1. 划定"底栏带" = 画布高度 80% 以下的区域；收集带内的所有图标；
   - 有跳转交互的图标 → 它代表的目标页就是候选 Tab；
   - 完全没交互的图标 → 说明它是"当前所在页"，也就是激活态的 Tab；
   - Tab 的文字 = 图标自己带的字，或者图标**正下方 30 像素内**的相邻文字（底栏通常是"图在上、字在下"）；
2. **共识投票**：只有出现在 **2 个以上页面**底栏里的目标，才算真正的 Tab 项。只在一页出现的底部图标是"页面级工具条"（比如锁屏、充电、自定义），必须排除掉；
3. **自指铁证**：真正的 Tab 页，它自己的底栏里一定有一个指向自己的图标（高亮激活态）。而"自定义""收集"这类跨页共享的功能按钮永远不会有自指——用这一条把两者区分开；
4. 最后生成一条规范的底栏（最多 5 项，符合移动端惯例），写进项目配置，所有页面渲染时注入**同一份**底栏。

**结果**：切页时底栏纹丝不动。

---

### 功能七：交互自动布线（把跳转关系连起来）

**它是什么**：一套**确定性算法**，根据页面之间的"拓扑关系"自动推导跳转连线，不需要 AI 再跑一遍。

**为什么要它**：AI 识别交互时会漏、会连错。而"返回键该返回""底部 Tab 该切页""点某个卡片该进对应详情页"这类规律是**可以推导出来的**，用规则做又准又免费。

**四类自动布线**：

| 类型 | 判定方式 | 结果 |
| :--- | :--- | :--- |
| **返回键** | 位于左上角（y≤90、x≤75），文案含"返回""<""back"，或是左上角一个 48×48 以内的小图标/按钮 | 绑定"返回上一页" |
| **底部 Tab 广播** | 元素在底栏带内（y≥680）、文案短（≤6 字）或是图标/文字类型，且文案命中了某个 Tab 主页面的关键词 | 绑定"跳转到对应主页面" |
| **出货槽唤起** | 文案含"出货"，或位于 y 550–600、宽≥150 且当前页名含"扭蛋" | 绑定"打开抽奖结果弹窗" |
| **功能入口下钻** | 按钮/图标/容器，或文案≥2 字，用语义关键词模糊匹配到某个页面 | 绑定跳转；如果目标是弹窗页，自动改成"打开弹窗" |

**它的三条"分寸感"规则**（重要，说明它不会乱改）：

1. **不覆盖**已有的"返回"连线和已有明确跳转目标的连线——人工调过的会被尊重；
2. **会升级**：如果之前连的是"跳转"但目标其实是个弹窗页，自动改写成"打开弹窗"（弹窗不该整页跳转）；
3. **会纠错**：自动清理历史上的误连，例如"开始探险"（这是玩法按钮，不是看说明书）被错连到"探险与属性说明弹窗"、"规则"被错连到说明弹窗的情况。

---

### 功能八：交互自动化验证（点一遍看看有没有坏）

**它是什么**：用无头浏览器（没有界面的 Chrome）把项目里所有可点元素**真的点一遍**，检查反应对不对。

**什么时候用**：改完数据后做回归；上线前做体检。

**它会断言什么**：

| 检查项 | 期望的行为 | 失败会告诉你什么 |
| :--- | :--- | :--- |
| 跳转 | 点下去后应该发出"跳转到 XXX"的信号 | "点击后未收到跳转消息（可能被遮挡或 runtime 缺失）" |
| 弹窗 | 点下去弹层应该出现；再点弹层里的关闭应该收起 | "点击后浮层未显示" / "浮层能打开但 back 未关闭" |
| 返回 | 点顶栏返回箭头应该发出"返回"信号 | "点击后未收到返回消息" |
| 脚本 | 检查本身是否正常执行 | "验证执行异常: …" |

**你会得到什么**：一份**失败清单**（全部通过就是空清单）。每条含页面名、类型、目标、原因。

**⚠️ 必须知道的边界**：它**只验证"点击有没有响应"，不检查"页面长得对不对"**。所以"0 failures"不等于"视觉没问题"。

**它的降级行为**：如果没装 Chromium，这个功能自动跳过，不会导致整个流程失败。

---

### 功能九：原型画布（主工作区）

**它是什么**：整个工具的主界面，一个可以无限拖动的画布，上面平铺着所有页面画框。

**什么时候用**：看全局关系、做标注、做微调、进预览。

**三个区域**：

| 区域 | 内容 |
| :--- | :--- |
| **左侧** | 设计稿列表（页面清单）、批量操作、底部统计（总元素数 / 交互事件 / 说明标注），并提示"拖动画布漫游，滚轮平滑缩放" |
| **中间** | 无限画布，每个页面是一个可拖动的区块，区块上方有带名称的浮动标签 |
| **浮层/右侧** | 手机壳模拟器（预览模式）与业务说明抽屉 |

**画布上的操作**：

| 操作 | 怎么做 |
| :--- | :--- |
| 平移画布 | 在空白处按住拖动 |
| 缩放 | 滚轮（以光标为锚点），范围 15% – 300% |
| 移动某个页面区块 | 拖它的标签栏（有 4 像素死区，防止误触） |
| 聚焦某一页 | 区块标签上的"放大聚焦此页"按钮，或按 `Shift+2` |
| 自适应全览所有画框 | 缩放条上的 `⛶` 按钮，或按 `Shift+1` |
| 回到 100% | 点缩放条中间的百分比数字，或按 `Ctrl+0` |
| 退出预览 | 按 `Esc` |

> 拖动区块时，界面会临时盖一层透明遮罩、暂时禁用事件响应——这是为了防止页面里的 iframe 抢走鼠标事件。

**左侧的批量操作**（先勾选页面）：

- 「**原型交互刷新**」——毫秒级，**不消耗 AI**，只按现有数据重新生成页面 HTML；
- 「**AI 重新识别**」——约 10–20 秒/页，**消耗 AI**，重新提取组件与元素。

**顶部两个开关**：

- 「**标注面板**」——控制业务说明卡片是否显示；
- 「**元素微调**」——进入"可以直接改页面上东西"的模式（预览模式下这个开关是灰的）。

---

### 功能十：业务说明与标注（评审的抓手）

**它是什么**：每个元素旁边挂一张卡片，写清楚"这是干嘛的"。

**什么时候用**：评审、交接、写玩法说明时。

**你会看到什么**：页面右侧（或指定位置）有一列说明卡片，每张卡片有：

- 拖拽手柄、标题、编辑铅笔按钮；
- 一个**交互徽标**：「⚡ 跳转」「⚡ 弹窗」「⚡ 切换」；
- 「去向: XXX」提示；
- 正文（占位文案是"双击编辑说明…"）。

**怎么编辑**：

- **双击正文**，或鼠标悬停时点铅笔按钮 → 弹出内联表单（"标题" + "说明"两个输入）；
- `Enter` 保存、`Esc` 取消、`Ctrl+Enter` 也保存；
- 改"标题"实际改的是**元素本身的名字**（所以画布上那个元素的名字也会跟着变）。

**怎么排序**：按住卡片左侧的手柄上下拖。画布上的顺序和模拟器抽屉里的顺序**是同步的**，改完会提示"📌 画布说明顺序已更新并同步"。

**引线**：说明卡片和它描述的元素之间会有一条折线连着，只在鼠标悬停或选中时高亮显示——避免满屏都是线。折线会自动绕开、自动计算竖折点。

**双向联动（很好用）**：点说明卡片 → 手机预览里对应的组件会**呼吸式发光高亮**并自动滚动到它；反过来点手机里某个组件 → 对应的说明卡片也会高亮并滚动过去。

---

### 功能十一：元素微调（在原型上直接改）

**它是什么**：开启后，你可以**直接在生成的页面上改东西**，像用一个极简编辑器。

**什么时候用**：AI 识别的小瑕疵懒得重跑（重跑要花钱花时间）、或者想让原型更精致一点时。

**能做什么**：

| 操作 | 怎么做 |
| :--- | :--- |
| 移动元素 | 直接拖动它（改的是元素的位置偏移） |
| 调整字号 | 鼠标滚轮（范围 8–48px） |
| 删除元素 | 右键点击 / `Alt+点击` / `Shift+点击` / `Delete` / `Backspace` / `X` |
| 撤销 | `Ctrl+Z` |
| 重做 | `Ctrl+Y` 或 `Ctrl+Shift+Z` |

**关于保存**：改完**不需要点保存**——工具会在你停手 500 毫秒后自动回存，并提示"✅ 微调已保存"。撤销历史最多保留 30 步。

---

### 功能十二：手机壳模拟器（像玩 App 一样走流程）

**它是什么**：一个带手机外框的预览窗口，能真正点击跳转、弹窗、切开关。

**什么时候用**：演示、评审、走查全流程。

**你会看到什么**：一个圆角 32px 的深色描边手机壳，固定宽度 375px，高度跟随页面。窗口大小变化时会自动等比缩放适应。

**怎么切页（三种方式）**：

1. 顶部下拉框「**切换页面**」直接选；
2. 点页面里可交互的元素，自然跳转（带左右滑入动画）；
3. 左上角悬浮的"返回上一页"按钮（不在首页时才出现）。

**它能模拟哪些交互**：

- **跳转**：点了会切到目标页；
- **弹窗**：点了会弹出浮层；点遮罩、点关闭按钮都能关掉；
- **返回**：正确地"回去"；
- **开关**：点击切换状态（含背景色变化和滑块位移动画）；
- **勾选框**：点击切换（橙色勾）；
- **选项卡**：点击在多个选项间轮换高亮；
- **按压触感**：交互模式下按钮按下会有 0.96 的弹性缩放。

**说明联动**：前面提到的"双向高亮 + 自动滚动"就是在这里生效的。

---

### 功能十三：多人协同防覆盖锁

**它是什么**：防止两个人同时改同一个页面导致互相覆盖。

**什么时候用**：多人同时在一个项目里做微调时自动生效，不需要手动开。

**它是怎么工作的**：

- 每个浏览器标签页有一个随机会话 ID；
- 当你进入某页的微调模式时，后台每 **3.5 秒**上报一次"我在改这页"（心跳）；
- 如果 12 秒没心跳，视为你已离开，锁自动释放。

**你会看到什么（四种提示，很显眼）**：

1. 顶部工具条出现橙色锁条：「「当前页」正被 XX 独占微调」；
2. 该页面区块的标签上出现玫红徽标「**XX 独占微调中**」；
3. 整个区块覆盖一层半透明遮罩 + 玫红虚线边框，框里写"XX 正在独占微调此页"，还贴心地告诉你"该页面已被独占锁定防覆盖，您可以自由微调其他页面"；
4. 模拟器抽屉标题旁出现琥珀色徽标「当前有人正在编辑」。

**如果你硬要保存别人的页面**会被拦下，提示：「🔒 保存被拦截:「页面」当前正被 XX 独占微调，无法覆盖其修改！」

**你自己的页面**会显示闪烁的绿色「微调中」标识，一看就知道哪页在跟着你。

> **注意**：这个锁记在后端进程的内存里。所以它只对"同一个后端实例"的多个用户生效；后端重启锁会消失（3.5 秒后前端自动恢复）。

### 功能十四：素材库

**它是什么**：一套内置的、风格统一的占位素材，让生成的原型不至于全是灰方块。

**里面有什么**（合计 67 个，全部是矢量 SVG）：

| 分类 | 数量 | 内容 |
| :--- | :--- | :--- |
| 人物头像 | 5 | `avatar-01` 〜 `avatar-05` |
| 产品图 | 4 | `product-01` 〜 `product-04` |
| 功能图标 | 52 | `home`、`star`、`bell`、`settings`、`search`、`trash`、`upload`… |
| 背景图 | 4 | `bg-01` 〜 `bg-04` |
| 特效 | 2 | 光晕、渐变 |

**还能放自己的素材**：在设计稿目录下建一个 `assets` 子目录，把图丢进去，启动时会**自动合并**进同一套素材库。

**配套接口**：可以直接按 ID 取素材（`/api/assets/icon-home`），也可以"随机取一张某类素材"（做一个随机头像生成器之类的功能时很有用）。

### 功能十五：自动化与运维类能力（不用管，但值得知道）

这几个功能平时看不见，但决定了工具好不好用：

| 能力 | 作用 | 你可以怎么用 |
| :--- | :--- | :--- |
| **启动自动生成** | 启动时自动扫描设计稿目录，把新图片追加到最近的项目并分析 | 设 `WIREFORGE_AUTO_ANALYZE=true`。设计稿一放进目录、重启后端就自动处理好了（默认关闭，避免误触发 AI 花费） |
| **数据库自动迁移** | 启动时自动检查并补齐缺失的字段（如 `canvas_x`、`html_content`、`sort_order`） | 老库升级新版本代码时**不用手工改表**，直接启动即可，不会报"Unknown column" |
| **大图智能预处理** | 超过 400KB 的设计稿，发送给 AI 前先等比缩到最长边 1280px 并转 JPEG | 手机超清长图原本 base64 有 4MB+，容易把 AI 接口拖超时；处理后体积降到 100–200KB，速度快 10 倍以上，且比例和文字清晰度不变 |
| **多环境数据隔离** | 提供了 `dev` 配置副本：独立数据库 `wireforge_dev`、独立设计稿目录、独立端口 8091 | 想在原项目旁边试新功能时，用 `dev` 副本跑，**完全不会污染原数据** |
| **全站跨域放行** | 后端对任意来源开放跨域 | 前后端分开部署时不用再配 CORS |

## 五、能力边界：目前做不到什么

诚实列出来，避免误用：

| 不存在的能力 | 说明 |
| :--- | :--- |
| **导出** | 没有"导出 HTML / 导出截图 / 导出 PDF"按钮。生成的 HTML 存在数据库里，通过接口访问 |
| **分享链接** | 没有分享功能。别人要看，得能访问同一个后端地址 |
| **多机型切换** | 手机壳只有 375px 一种尺寸，不能切 iPhone / Android / 平板 |
| **显式"线稿 / 高保真"视图切换** | 没有这个开关。真实机制是：该页已生成整页 HTML 就直接渲染 HTML，没生成就退回组件式渲染 |
| **对齐线 / 吸附 / 自动排版面板** | 画布是自由拖动，没有智能对齐参考线，也没有小地图 |
| **手动拖引线折点** | 说明卡片的引线是自动算的。数据里有引线坐标字段，但界面上没有编辑入口 |
| **拖动标注框自由摆放** | 同上，界面未开放 |
| **深色主题** | 全站只有浅色主题 |
| **登录与权限** | 完全没有账号体系。**任何能访问到这个服务的人都能看到和修改所有项目**——所以不要直接暴露到公网 |
| **视觉质量自动判定** | 「交互验证」只检查"点了有没有反应"。视觉对不对必须人眼看 |

## 六、上手建议

### 怎么开始（第一次用）

1. 把设计稿图片放进 `designs` 目录（建议按模块建子文件夹，如 `装扮修改/`、`商城/`）；
2. 打开工具 → 「新建项目」；
3. 进项目 → 点「**扫描设计稿**」；
4. 点「**AI 生成原型**」，等它跑完（页数越多越久）；
5. 点「**进入原型画布**」→ 顶部「**预览原型**」，把流程点一遍。

### 日常迭代的省 Token 路线（推荐）

设计稿只有小幅调整、或者只想看渲染效果变化时，**不要**重跑 AI，按这个顺序来：

```
扫描设计稿  →  AI 生成原型（只处理新页）  →  原型交互刷新（零 AI）  →  交互验证
```

如果只想改某一页，用左侧的「**原型交互刷新**」（毫秒级）或单页"重新生成"；

只有在"元素识别本身错了"（比如把按钮认成了文本框）的时候，才用「**AI 重新识别**」。

### 遇到问题时的排查顺序

| 现象 | 先看这里 |
| :--- | :--- |
| 点了没反应 | 跑「交互验证」拿失败清单，看是哪个元素连错了 |
| 页面下半截空白 / 内容溢出 | 多为原图比例问题，重跑该页「原型交互刷新」 |
| 切换页面时底栏/导航跳动 | 说明变体页没对齐，重跑一次「AI 生成原型」会触发对齐 |
| 有裂图 | AI 引用了不存在的素材；重渲染会自动清理，或检查素材库 |
| 提示"页面正被 XX 独占微调" | 等 12 秒对方心跳超时，或让对方释放；也可以先微调别的页 |
| 保存被拦截 | 同上，说明对方正在改这页，避免互相覆盖 |

---

## 七、一句话总结

**WireForge = 让 AI 负责"看懂设计稿"，让确定性算法负责"把原型画稳"，让人负责"讲清楚每一块的业务意图"。**

三件事分开做，各司其职——所以它既能自动、又稳定，还便宜。
